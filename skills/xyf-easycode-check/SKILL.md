# 架构与代码核对

确定项目后，运行前及每批写入前重读 `<project>/docs/xyf-easycode/PromptsRules.md`；未部署先读[模板](../xyf-easycode-install/PromptsRules.md)并说明缺项，复制交给 install 按授权处理。读取失败则暂停。

## 依据与边界

沿用项目、架构和范围；未限定则查全部。架构默认 `<project>/docs/xyf-easycode/html/software_architecture.js`。已有路径沿用；核实源码入口及路径，解决基准冲突，模板不作需求；排除无关依赖、缓存和生成文件。

JS 用 [ProjectFile.parse](../xyf-easycode-install/html/assert/project-file.js) 解析，旧 JSON 用 `JSON.parse`，用 [Model.validate](../xyf-easycode-install/html/assert/model.js) 校验；不执行配置、不补默认值；其他文档按条款核对，字段见[数据说明](../xyf-easycode-install/html/references/architecture-data.jsonc)。

静态检查，不运行测试；代码、架构及状态只读，主代理独写计划。

## 模块检查项

| 内容 | 检查要求 |
| --- | --- |
| 模块信息 | 用途、代码名称、语言、位置、分层符合约定 |
| 功能需求 | 正常路径、边界、结果、副作用逐条落实，无空实现或假结果 |
| 依赖 | 导入、注册、调用、运行前提满足约定 |
| 模块参数 | 名称、类型、用途、必填及规定默认值一致 |
| 数据结构 | 结构、字段名称、类型、含义和实际数据一致 |
| 方法及输入输出 | 方法存在且可调用，职责、参数、返回值符合约定 |
| 流程与错误处理 | 顺序、分支、处理和错误传播符合约定 |
| 消息事件 | 名称、方向、消息参数、流程、发送接收关系一致 |
| 测试 | 规定步骤、断言及预期结果有覆盖；测试及产物在 `<project>/docs/xyf-easycode/tests/`，静态检查不代表运行通过 |
| 实现证据 | 来源路径、行号、代码对象及状态符合现状 |

方法在 `interfaces` 中；输入输出为空须查约定；默认值缺失或为空不代表零或空串。`relations` 仅是画布标注，状态不能代替代码证据。按明确约定判定；布局、颜色仅查配置合法性。

## 并行查证与计划

任务 ID 用本地时间 `yyyy_mm_dd_hh_mm_ss_ms`（24 小时制，毫秒 3 位），保存为 `<project>/docs/xyf-easycode/plans/<任务ID>.md`。重名重新取时间，恢复或复查沿用 ID；被 code 调用时更新其指定计划。
主代理建档，记录项目、架构及关联计划完整路径、初始基准（含未提交修改）、各检查项负责人、覆盖和证据。差异转成修复任务，逐项列问题、原因、文件行号、写入范围、改法、依赖顺序、验收、授权、进度和下一步。待确认项标明且不执行。每批及交接前更新对应条目，保留其他进度；恢复先读再核实，编码验收后清理。

| 阶段 | 要求 |
| --- | --- |
| 建立清单 | 一次解析架构，记录文档、源码、配置内容基准及未提交修改；按模块和成员 ID 列全检查项，`rg` 定位、按文件阅读。 |
| 分配检查 | 按模块或依赖组分给子代理，提供路径、基准、条款、检查项、授权；每项一人负责；公共组件一人检查，调用方核对调用行为。小任务或代理不可用时串行。 |
| 追查证据 | 沿入口、注册、调用和数据流查证，回传覆盖、证据和差异。疑点追查；缺权限或业务决定时具体提问，继续其余检查，不猜测。 |
| 汇总复核 | 主代理复核差异、跨模块调用及完整覆盖；补查冲突和缺项，核对基准，重查受影响项。 |

首次查全；后续仅复用记录完整且条款、源码、依赖、配置和覆盖不变的项；变化及受影响调用方复查。

## 交付

交付计划路径及摘要，供 [code](../xyf-easycode-code/SKILL.md) 直接执行。同根因合并，列全受影响成员。查全且无差异，计划写明“未发现不符合项，无需修复”；未查完标为未完成，不声称无问题。

已批架构调整交给 [plan](../xyf-easycode-plan/SKILL.md)，不自动修复。
