# 按计划开发与交付

## 依据与交接

沿用已确认项目、架构、范围和授权；默认架构为 `docs/xyf-easycode/html/software_architecture.js`。读取 plan 或 check 输出的 `<project>/docs/xyf-easycode/plans/<任务ID>.md`。ID 为本地时间 `yyyy_mm_dd_hh_mm_ss_ms`（24 小时制，毫秒 3 位）；恢复沿用原 ID。缺设计交给 [plan](../xyf-easycode-plan/SKILL.md)，缺计划由 [check](../xyf-easycode-check/SKILL.md) 生成。保留用户修改，不擅自改变架构；变更设计须确认方案和写入范围。网页部署交给 [install](../xyf-easycode-install/SKILL.md)。

主代理登记关联计划完整路径及 ID；固定保留任务初始基准（含未提交修改），每轮检查版本另存。统一更新任务、负责人、可写文件、授权、进度、证据和下一步；每批工作及交接前保存。恢复先读计划，再核对文档、源码、依赖及未提交修改。

## 执行流程

步骤 2 至 4 按模块分批推进。

| 阶段 | 负责人及通过要求 |
| --- | --- |
| 1. 检查与计划 | 核对计划、现状及授权，按任务、顺序和验收执行，不重复规划。缺项或过期部分由 check 补查并回写当前计划。批量写入须先明确方案及文件范围并获批准；沿用范围内有效授权，新增或扩大范围重新确认。关键约定缺失时查证或提问，暂停受影响部分。 |
| 2. 模块开发 | 子代理每次处理一个模块，依赖可用后再开发；新前置模块先通过步骤 3、4。按约定实现名称、类型、默认值及行为，复用已有代码；方法和事件流程逐步写编号注释。按架构测试要求或已确认需求验证真实行为，禁止空实现和假结果。所有测试入口、用例、数据、临时文件、缓存、日志、覆盖率、报告、工作目录及相关构建和类型检查输出，均在 `<project>/docs/xyf-easycode/tests/` 下；并行测试分目录，业务源码和复用工具可从外部引用，不迁移或删除旧测试。通过后停止写入再交接。 |
| 3. 文档核对 | 主代理按本批模块及受影响代码组织 check 回写当前计划，亲自复核差异、证据及完整覆盖，源码保持只读。差异退回步骤 2，修复后复查；核对通过才进入独立审查，不改架构状态。 |
| 4. 独立审查 | 非开发者、非修复者使用 [review-agent](../review-agent/SKILL.md) 只读审查本批最终代码。缺陷退回步骤 2，重新测试及核对后独立复查；缺陷全部处理才通过。 |
| 5. 整体验证 | 模块全部通过、写入者停止后，主代理亲自按 review-agent 审查原始基准以来的完整改动及跨模块行为。在步骤 2 的测试目录规则下完成集成、回归和必要构建；修复后重跑受影响测试，再重复步骤 3、4，并复核最终完整改动。 |
| 6. 验收交付 | 主代理核对最终内容、全部计划及证据；最终补充测试仍遵守步骤 2。关联计划全部完成且开发、测试、核对、审查通过后，逐份核实项目、独立 ID 和完成状态，仅删除本次登记且全部事项已完成的计划文档；其余保留，架构文件不删。简表交付改动、实际验证和结果。 |

## 协作规则

独立任务可并行，共享文件串行；一个模块或文件同一时间一位写入者。提供路径、模块 ID、范围、基准、授权和验收要求；子代理回传结果，主代理落盘。架构、源码或依赖变化时重查受影响项，不沿用过期结论。

必要测试或独立审查缺失时保留计划并说明具体障碍，不声称验收通过；代理不可用时先协商调整。提交、推送、合并或发布须用户明确要求。
