# XYF-ARCHIFY

## 总目标

通过采访明确项目需求，整理功能清单，再结合现有架构提出分层、模块职责和接口方案。用户确认后生成 `archify.json`，提供可继续编辑的架构网页。

`archify.json` 是架构依据。本技能只讨论和维护架构，不阅读业务源码或判断代码实现；代码向架构看齐的工作由 [xyf-code](../xyf-code/SKILL.md) 负责。

## 执行流程

每步先完成工作，再用简短表格呈现结果，请用户确认。**收到明确确认后才能进入下一步；未回复、工具运行成功或已有文件都不等于确认。** 用户提出修改时，调整当前结果并重新确认；已明确确认且未变化的内容直接沿用。

目录以本次任务开始时的工作目录为边界，默认在当前目录工作，新项目只能建在其子目录。写入前解析目标绝对路径，确认仍在边界内；未经用户明确允许，不得另建父级、同级或外部项目。技能安装目录只是工具来源，不是项目目录。用户限定只讨论或只生成配置时，省略相应的部署操作。

### 1. 判断项目并准备工作区

**目标：** 明确项目位置、现有架构和网页是否需要初始化。

**步骤与约束：**

- 根据用户说明和现有架构判断新旧项目。已有项目先读当前 `archify.json`，概括分层、模块、职责、接口和依赖；文件缺失时询问已有设计，不能据此认定为新项目，也不转去分析业务源码。
- 工作区默认 `<project>/docs/archify/`，仅生成 JSON 也沿用此位置；已有或用户指定路径在目录边界内直接复用，保留配置和网页定制。需要网页且尚未初始化时，将技能 `tools/` 复制到 `<workspace>/tools/`；沿用已指定或现有的网页语言，未知才询问，并调用 [xyf-web-language](../xyf-web-language/SKILL.md) 只处理该副本。
- 首次部署时，用副本的 `html/scripts/build.mjs --runtime <workspace>/index.html` 生成入口，复制副本的 `html/` 到 `<workspace>/html/`，从后者的 `server.mjs` 启动服务。工作区的 `<workspace>/archify.json` 是唯一配置；缺失时用模型创建独立 ID 的空白配置。服务和访问说明见[工具说明](../../tools/README.md)，不得启动工具副本内的服务读写模板。

**完成条件：** 用户确认项目位置、新旧项目判断及现有架构摘要；需要部署时，网页已能加载当前配置，地址和重启方式已记录。

### 2. 采访项目需求

**目标：** 充分理解用户想解决什么问题、实现什么效果。

**步骤与约束：**

- 用大白话围绕使用场景、期望结果、本次范围和关键限制采访，一次只问一个关键问题；已知内容不重复问。有实际取舍时给简短选项和建议，不扩展无关功能，不盘问算法、库或存储实现。
- 全新项目才确认编程语言和部署平台；已有项目沿用架构约定，除非用户要求变更。
- 信息足以明确功能和架构范围时，就总结并请用户确认，不继续深挖实现细节，也不要求用户先想好模块或接口。

**完成条件：** 目标、场景、范围和限制已明确，用户确认理解准确。

### 3. 整理功能需求清单

**目标：** 将采访结果拆成明确、可核对的功能需求。

**步骤与约束：**

- 逐项说明要实现的功能、主要输入、预期结果和关键业务规则；区分本次新增、调整及保留的功能。
- 补问影响功能含义的缺口，不擅自增加业务规则，也不要求在终端逐字段细聊。

**完成条件：** 用户确认功能清单完整、范围正确，关键规则没有歧义。

### 4. 提出并确认架构方案

**目标：** 用合理的分层、模块和接口覆盖已确认的功能需求。

**步骤与约束：**

- 结合当前 `archify.json` 提出复用、新增或优化哪些模块；新项目给出初始架构。说明各层作用、模块职责与依赖，以及每个主要接口的用途、输入输出和关键行为。
- 按“分层 → 模块 → 接口”展示方案，并列出每项功能由哪些模块和接口承担，检查遗漏、职责重叠及接口冲突。
- 逐个与用户确认受影响模块及接口。能从已确认内容确定的配置细节自行整理，影响业务含义或对外行为的选择交给用户。

**完成条件：** 用户确认模块职责、主要接口和需求覆盖关系；没有影响架构方案的关键疑问。

### 5. 生成 archify.json

**目标：** 将确认方案保存成有效配置，交给用户继续核对。

**步骤与约束：**

- 仅将已确认方案写入正式配置。写前重读当前 JSON，处理版本冲突和已知未保存修改，保留稳定 ID、无关内容和布局；依照[数据指南](../../tools/html/templates/archifytemplate.template.jsonc)及[模型](../../tools/html/assets/model.js)完整记录需求、分层、模块、依赖和接口，不编造源码证据。新增布局按层从上到下，模块不重叠，连线清晰。
- 使用[文件工具](../../tools/html/scripts/files.mjs)校验、带版本检查保存并回读比较。交付网页时，按[检查说明](../../tools/README.md#maintain)核对配置、服务及实际页面，确保读写同一配置；只要求 JSON 时不增加网页部署与检查。

**完成条件：** 配置校验和保存回读通过，用户确认交付结果。交付配置路径、实际网页地址（如有）及检查结果；未完成或未验证的事项明确列出，不自动开始编程。
